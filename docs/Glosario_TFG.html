Glosario de términos

A continuación se recogen los términos específicos del proyecto y los conceptos técnicos que se emplean a lo largo del documento, agrupados por ámbito. Su lectura previa facilita la comprensión del resto de la memoria.

1. Nomenclatura del proyecto

TérminoDefinición
SaaSphere Nombre de la empresa ficticia y de la plataforma global objeto del proyecto. Engloba la infraestructura física, los servicios desplegados y el modelo comercial de suscripción mensual ofrecido a los clientes.
LeIA Nodo físico dedicado a la inteligencia artificial. Aloja el agente OpenClaw y los modelos de lenguaje locales servidos a través de Ollama. Cuenta con GPU dedicada para acelerar la inferencia.
OpenClaw Aplicación Python que implementa el agente de inteligencia artificial encargado de observar el clúster, razonar sobre su estado y ejecutar acciones acotadas. Es el software que se ejecuta dentro del nodo LeIA.
Matrix Máquina virtual que actúa como nodo principal del clúster K3s. Centraliza el orquestador, el proxy inverso Traefik y el registro privado de imágenes.
Sauron Máquina virtual dedicada a la monitorización. Aloja el stack Prometheus, Grafana, Loki, Alertmanager, Blackbox y Promtail.
Heimdall Máquina virtual que ofrece acceso remoto seguro mediante una pasarela VPN basada en WireGuard.
Fallback Nodo físico de respaldo, en espera durante el funcionamiento normal del sistema. Su activación se produce cuando el nodo principal queda fuera de servicio o supera los umbrales de carga definidos.

2. Conceptos del agente OpenClaw

TérminoDefinición
Caso de uso (CaseUse) Modo de operación con el que se invoca al agente. Cada caso de uso determina el modelo de lenguaje empleado, el conjunto de herramientas disponibles y la severidad por defecto de las acciones. Ejemplos: chat, análisis profundo, health loop, resumen diario.
Herramienta (tool) Función registrada que el agente puede invocar de forma controlada para interactuar con el sistema. Se clasifican en herramientas de lectura (consulta de métricas, logs o estado) y de mutación (modificación del clúster).
Mutación Toda acción que modifica el estado de la infraestructura: despliegue, eliminación, pausa o reanudación de un servicio, reinicio de un pod, escalado, etc. Se diferencian de las acciones de lectura, que no alteran el sistema.
Severidad Clasificación de cada mutación en uno de tres niveles: AUTONOMOUS (puede ejecutarse sin intervención humana), NORMAL (requiere aprobación humana) y CRITICAL (requiere aprobación humana, con recordatorios periódicos y mayor tiempo de espera).
Aprobación Mecanismo de control humano previo a la ejecución de las mutaciones de severidad NORMAL o CRITICAL. Se solicita al operador a través de Telegram y se confirma o rechaza mediante botones en línea.
Política (policy) Conjunto de reglas que se evalúan antes de toda mutación. Bloquea acciones sobre namespaces de sistema, manifiestos con recursos prohibidos y operaciones fuera del ámbito autorizado del agente.
Modo del agente Estado global de OpenClaw. Toma uno de los tres valores siguientes:
  • normal: operación habitual.
  • dry_run: las mutaciones se simulan pero no se ejecutan.
  • paused: el agente no responde a ninguna entrada.
Ledger / registro de acciones Tabla persistente que almacena cada acción intentada o ejecutada por el agente, junto con su resultado, su severidad y la decisión de aprobación correspondiente. Proporciona trazabilidad completa.
Health loop Tarea periódica de comprobación del estado del clúster. Si detecta una anomalía, escala a un análisis profundo de forma autónoma.
Watcher Proceso que escucha eventos de Kubernetes en tiempo real y reacciona ante incidencias sin esperar al siguiente ciclo programado.
Scheduler Componente que ejecuta las tareas programadas del agente: comprobaciones periódicas, resúmenes, verificación de copias de seguridad y optimización de pods.

3. Modelos de lenguaje e inferencia

TérminoDefinición
LLM Acrónimo de Large Language Model. Modelo estadístico entrenado sobre grandes volúmenes de texto, capaz de generar respuestas en lenguaje natural y de invocar herramientas externas mediante el patrón conocido como function calling.
Ollama Servicio local que permite ejecutar modelos de lenguaje sobre el hardware del propio usuario y exponerlos mediante una API compatible con la de OpenAI. Evita la dependencia de proveedores externos.
Qwen3 Familia de modelos de lenguaje empleada en el proyecto. Se utilizan dos variantes en local: qwen3:8b, más rápida y orientada a tareas de lectura, y qwen3:32b, más lenta pero con mayor capacidad de razonamiento, usada en mutaciones y análisis profundo.
Modo think Extensión de Qwen3 que reserva una fase de razonamiento explícito antes de emitir la respuesta final. Mejora la calidad del análisis a costa de un mayor tiempo de inferencia. Se activa en los casos de uso que requieren decisiones complejas.
Pydantic AI Biblioteca de Python que estructura la comunicación entre la aplicación y el modelo de lenguaje, garantizando que las entradas y salidas se ajusten a esquemas tipados.
VRAM Memoria dedicada de la tarjeta gráfica. Determina el tamaño máximo de modelo que puede cargarse íntegramente en la GPU. Los modelos que no caben se reparten entre VRAM y memoria del sistema, con la consiguiente penalización de rendimiento.
Alucinación Fenómeno por el cual un modelo de lenguaje genera una respuesta plausible pero incorrecta o inventada. Justifica la necesidad de validaciones externas y de aprobaciones humanas sobre las acciones críticas.

4. Orquestación y contenedores

TérminoDefinición
Contenedor Unidad de software autocontenida que empaqueta una aplicación junto con sus dependencias y se ejecuta de forma aislada sobre un núcleo Linux compartido.
Docker Plataforma estándar para construir y ejecutar contenedores. En este proyecto se emplea como base de las imágenes desplegadas.
Kubernetes Orquestador de contenedores que automatiza el despliegue, escalado y mantenimiento de aplicaciones distribuidas.
K3s Distribución ligera y certificada de Kubernetes diseñada para entornos con recursos limitados. Conserva la compatibilidad con los manifiestos y herramientas estándar del ecosistema.
Clúster Conjunto de nodos coordinados por Kubernetes para ejecutar y gestionar contenedores de forma unificada.
Nodo Máquina, física o virtual, que forma parte del clúster y aporta sus recursos para la ejecución de cargas de trabajo.
Pod Unidad mínima de ejecución en Kubernetes. Agrupa uno o varios contenedores que comparten red y almacenamiento.
Deployment Recurso que describe el estado deseado de una aplicación: número de réplicas, imagen, recursos y estrategia de actualización.
Namespace Mecanismo de separación lógica dentro del clúster. Cada cliente del proyecto se aísla en su propio namespace para evitar interferencias y simplificar la administración.
Tenant Cliente o instancia desplegada en la plataforma. En el proyecto, cada tenant corresponde a un namespace etiquetado con saasphere.io/tenant=true y a un conjunto de recursos generados a partir de plantillas. Es el concepto central del modelo multitenant.
Multitenant Arquitectura en la que una misma infraestructura presta servicio a múltiples clientes manteniendo el aislamiento entre ellos.
Manifiesto Fichero declarativo en formato YAML que describe los recursos de Kubernetes a crear. En el proyecto se generan dinámicamente a partir de plantillas Jinja2.
Ingress Recurso de Kubernetes que define las reglas de entrada del tráfico HTTP/HTTPS al clúster, asociando dominios y rutas con los servicios internos.
Traefik Proxy inverso integrado en K3s. Enruta las peticiones externas al pod correspondiente según el dominio del cliente y gestiona los certificados TLS de forma automática.
Let's Encrypt / ACME Autoridad certificadora gratuita y protocolo asociado para la emisión y renovación automatizada de certificados TLS. Garantiza el cifrado HTTPS de todos los servicios expuestos.
Registry privado Repositorio interno de imágenes de contenedor, accesible únicamente desde la red local del proyecto. Permite distribuir imágenes propias sin depender de servicios externos.
Taint NoSchedule Marca aplicada a un nodo que impide que Kubernetes le asigne nuevos pods salvo que estos toleren expresamente la marca. Se utiliza en el nodo Fallback para reservarlo a situaciones excepcionales.
RBAC Acrónimo de Role-Based Access Control. Sistema de control de acceso de Kubernetes basado en roles. Permite limitar las acciones que cada cuenta puede ejecutar sobre el clúster. La cuenta de OpenClaw dispone únicamente de los permisos imprescindibles para su operativa.
Plantilla Jinja2 Plantilla de texto parametrizada que, al combinarse con un conjunto de variables, genera un manifiesto YAML listo para aplicar. En este proyecto se emplean para los tres tipos de tenant soportados.

5. Observabilidad y alertas

TérminoDefinición
Observabilidad Capacidad de un sistema para exponer información suficiente (métricas, registros y trazas) que permita inferir su estado interno a partir de su comportamiento externo.
Métrica Valor numérico medido a intervalos regulares que refleja un aspecto del sistema (uso de CPU, memoria, número de peticiones, etc.).
Prometheus Sistema de monitorización basado en la recolección periódica de métricas mediante consultas HTTP a los puntos de exposición de cada servicio.
Grafana Plataforma de visualización que representa las métricas almacenadas en Prometheus y otras fuentes mediante paneles personalizables.
Loki Sistema de agregación y consulta de registros (logs), diseñado para integrarse con Grafana de forma análoga a Prometheus pero aplicado a texto.
Promtail Agente que recolecta los logs locales de cada nodo y los envía a Loki.
Blackbox exporter Componente de Prometheus que prueba la disponibilidad de servicios externos mediante sondas HTTP, TCP o ICMP.
Alertmanager Servicio asociado a Prometheus que recibe las alertas generadas por las reglas configuradas y las distribuye a los destinos correspondientes (Telegram, webhook hacia OpenClaw, etc.).
Webhook Endpoint HTTP expuesto por una aplicación que recibe notificaciones automáticas desde otro sistema. En el proyecto, OpenClaw expone un webhook al que Alertmanager envía las alertas para su análisis.
Dashboard Panel visual en Grafana que agrupa varias métricas o registros con el fin de evaluar el estado del sistema de un vistazo.
Node exporter Agente que expone las métricas del sistema operativo (CPU, memoria, disco, red) para que Prometheus las consulte.
Kube-state-metrics Componente que expone métricas sobre el estado de los recursos de Kubernetes (pods, deployments, nodos) para su consumo desde Prometheus.

6. Red y seguridad

TérminoDefinición
VPN Acrónimo de Virtual Private Network. Red virtual que cifra el tráfico entre dispositivos remotos y la infraestructura interna, ofreciendo acceso seguro desde el exterior.
WireGuard Implementación moderna de VPN, basada en criptografía simétrica y con una configuración más sencilla que las soluciones tradicionales. Se emplea en el nodo Heimdall para el acceso administrativo remoto.
TLS / HTTPS Protocolos que cifran las comunicaciones entre cliente y servidor. En el proyecto se aplican a todos los servicios expuestos al exterior mediante certificados emitidos por Let's Encrypt.
Fail2ban Servicio que analiza los registros del sistema y bloquea de forma automática las direcciones IP que muestran patrones de ataque, como intentos repetidos de inicio de sesión.
UFW Acrónimo de Uncomplicated Firewall. Frontal simplificado para la configuración del cortafuegos del sistema operativo.
auditd Subsistema de auditoría del núcleo Linux. Registra las llamadas al sistema relevantes para el análisis posterior de actividad sospechosa.
Hardening Proceso de reforzar la seguridad de un sistema mediante la desactivación de servicios innecesarios, la aplicación de actualizaciones, el endurecimiento de la configuración y la implantación de mecanismos de auditoría.

7. Modelo de servicio y conceptos generales

TérminoDefinición
SaaS Acrónimo de Software as a Service. Modelo de distribución de software en el que la aplicación se aloja y mantiene en la infraestructura del proveedor, y el cliente accede a ella mediante una suscripción.
CMS Acrónimo de Content Management System. Aplicación que permite al cliente gestionar el contenido de su web sin intervención técnica directa. WordPress es un ejemplo característico.
Landing page Página web única, estática y orientada a un objetivo concreto, normalmente la presentación del cliente o la captación de contactos.
Snapshot Captura del estado completo de una máquina o sistema en un instante determinado. Permite restaurar dicho estado en caso de fallo.
Hipervisor Capa de software que permite ejecutar varias máquinas virtuales sobre un mismo hardware físico. En el proyecto se emplea VMware ESXi.
VMware ESXi Hipervisor de tipo 1, instalado directamente sobre el hardware sin necesidad de un sistema operativo anfitrión. Aloja las tres máquinas virtuales del proyecto (Heimdall, Sauron y Matrix).
Dry-run Ejecución simulada de una operación. Se realizan todas las validaciones y se produce el resultado teórico, sin aplicar cambios reales sobre el sistema.
SQLite Motor de base de datos relacional ligero, embebido y sin servidor. Almacena toda la información persistente del agente OpenClaw.
SQLModel Biblioteca de Python que combina las funcionalidades de Pydantic y SQLAlchemy para definir modelos de datos tipados que se traducen automáticamente a tablas SQL.
aiogram Biblioteca asíncrona de Python para la creación de bots de Telegram. Gestiona los comandos del operador y los botones de aprobación en línea.
FastAPI Marco de desarrollo web en Python orientado a APIs de alto rendimiento. Expone los puntos de acceso HTTP del agente, entre ellos /health, /metrics y el webhook de Alertmanager.
